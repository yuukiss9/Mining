## I. 需求之外但做了的部分（便于答辩时说明）

| 项 | 位置 | 价值 |
| --- | --- | --- |
| 候选表定位（只把命中页与表送进模型） | `pdf.PdfTable.score_against` / `candidate_tables` | 真实 NI 43-101 动辄上百页，全量喂模型既贵又容易淹掉信号 |
| "数据行数量"作为候选表闸门 | `pdf.PdfTable.data_row_count` | 实测：正文碎片能蹭到 11.6 分的关键词分，但凑不出连续数据行 |
| LLM 端点三层连通性自检 | `scripts/check_llm.py` | 降级设计的副作用是"配置写错不报错"，必须显式暴露 |
| PDF 文本层体检（判定是否需要 OCR） | `scripts/pdf_health.py` | 把"要不要引入 OCR"从主观猜测变成一条命令的客观判定，并区分整份 / 单页两种处置范围；阈值与 `ni101/pdf.py` 同源，避免体检结论与流水线行为互相矛盾 |
| 端到端自检固化为脚本 | `scripts/smoke_check.py` | 每个检查带证据值 + 退出码，可当 CI 闸门 |
| 退出码语义 | `run_pipeline.py` 结尾 | `0` = 无硬给，`1` = 存在硬给 |
| API Key 的 ASCII 前置校验 | `config.assert_ascii` | 从网页粘贴带全角字符时，原生报错完全看不出是 Key 的问题 |
